#### AUTH1 — Admin area is open to every registered user (CRITICAL)

> Principle IV: "Protected admin, account, and API functionality MUST declare authorization requirements explicitly at the boundary... Implicit or assumed protection is insufficient for security-sensitive behavior."

Evidence:

```csharp
// TeachSpark.Web/Areas/Admin/Controllers/BaseAdminController.cs:6-8
[Area("Admin")]
[Authorize] // Require authentication for all admin controllers
public abstract class BaseAdminController : Controller
```

- All 9 admin controllers inherit this base; none adds a role or policy.
- No `Roles`, `IsInRole`, `AddRoles` or authorization policy exists anywhere in the code.
- Registration is open (`Areas/Identity/Pages/Account/Register`) and `Program.cs:40` sets `RequireConfirmedEmail = false`.
- `Views/Shared/_Layout.cshtml:71-73` shows the Admin menu to every signed-in user.

Impact: anyone can create an account and immediately manage API keys, delete worksheets, edit prompt templates and import standards.

Intent: the admin boundary should separate operators from teachers, not just signed-in users from anonymous ones.

Recommendation: add Identity roles (`AddRoles<IdentityRole>()`), seed an Admin role for the operator account, change the base class to `[Authorize(Roles = "Admin")]` (or a named policy), and hide the Admin menu unless `User.IsInRole("Admin")`. Add an integration test asserting a non-admin user gets 403 on `/Admin/Dashboard`.

#### AUTH2 — Model API is anonymous (HIGH)

> Principle IV (as above): endpoints that require protection "MUST use authorization attributes or policies close to the protected surface."

Evidence: `ModelsController` (`[ApiController]`, `[Route("api/[controller]")]`) has no `[Authorize]`. Anonymous callers can:

- `POST /api/models/refresh` (line 200) — refreshes the model registry from OpenAI.
- `GET /api/models?forceRefresh=true` (line 27) — bypasses the cache on every request.
- `POST /api/models/estimate-cost` and `/{modelId}/estimate-cost`.

Intent: calls that spend the OpenAI key or mutate shared state should only be reachable by the people allowed to trigger them.

Recommendation: add `[Authorize]` at the class level; mark `RefreshModels` admin-only (same policy as AUTH1); leave any truly public read endpoint explicitly `[AllowAnonymous]` so the decision is visible.

#### FE1 — Admin assets bypass the webpack pipeline (HIGH)

> Principle II: "Asset changes MUST flow through the existing webpack build and generated wwwroot outputs."

Evidence:

- `_AdminLayout.cshtml:25-27` — 3 DataTables stylesheets from `cdn.datatables.net`.
- `_AdminLayout.cshtml:186-195` — 10 scripts from `cdn.datatables.net` and `cdnjs.cloudflare.com` (DataTables 2.3.2, Buttons, Responsive, jszip, pdfmake).
- `Areas/Admin/Views/Dashboard/Index.cshtml:226` — `https://cdn.jsdelivr.net/npm/chart.js` with **no version pin**, so a new major release changes production behavior without a code change.
- `src/scss/site.scss` already imports `datatables.net-bs5` CSS through webpack, so admin pages load DataTables styles twice from two sources.
- The redesign adds a Google Fonts stylesheet to both layouts. Strictly, that is also an asset outside webpack; self-hosting via `@fontsource/be-vietnam-pro` and `@fontsource/inter-tight` would bring it into the pipeline.

Intent: every asset the site depends on should be versioned, reproducible and built by the same pipeline.

Recommendation: install `datatables.net-*`, `jszip`, `pdfmake` and `chart.js` as npm dependencies, add an `admin` webpack entry, and load it via `AssetsService.GetAssetPath`. Until then, at minimum pin Chart.js to an exact version.

#### TEST1 — Test coverage is two smoke tests (HIGH)

> Principle I: "Every new feature, bug fix, and materially changed behavior MUST include automated tests."

Evidence: `TeachSpark.Tests/BasicIntegrationTests.cs` (71 lines) contains 2 test methods and a `WebApplicationFactory`. No tests cover authorization boundaries, worksheet generation, the LLM services, admin CRUD or CSV import.

The constitution treats legacy gaps as forward-looking, so this is HIGH rather than CRITICAL. It becomes blocking for any new work: AUTH1 and AUTH2 fixes must ship with tests.

Intent: each security boundary and core flow should have a test that fails if it regresses.

Recommendation: start with integration tests on the existing factory: anonymous → 302/401 on protected routes, non-admin → 403 on `/Admin/*`, and a generation request with a stubbed `ILlmService`.
